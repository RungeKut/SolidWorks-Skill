# Работа с репозиторием

Набор — `https://github.com/RungeKut/SolidWorks-Skill`, ветка `main`,
публичный. **Порядок, обезличивание, стоп-лист, автор, соавторы, форк и
разбор PR, GitHub без gh — соседний скилл skill-skill, `knowledge/40_СРЕДА/
40-02` и 40-03.** Коротко: в начале `git -C <корень> pull --rebase`
(конфликт — разобрать до моделирования: база важнее текущей задачи); после
правки `git diff` глазами → `python tools/check_docs.py --project "<папка
проекта>"` → `git add <файлы>` → `git commit` → **`git push` сразу**.

Отправлять после каждой смысловой правки — новой записи в `knowledge/`,
изменения `swkit/`, правки `SKILL.md`, — а не в конце сессии. Одна правка —
один коммит с внятным сообщением.

## Обезличивание: изделие

Набор — знание об инструменте, а не история сборки изделия. Кроме общего
списка, в файлы, текст коммита и PR не попадают:

* название изделия, его марка, модель, обозначение;
* имена деталей, сборок и чертежей проекта — как в дереве, так и в файлах;
* габариты, массы и прочие числа изделия, если они не нужны самому приёму;
* характерные узлы, по которым изделие узнаётся и без названия;
* пути к папке проекта.

Остаётся всё, ради чего запись пишется: поведение API, сигнатуры, углы и
допуски приёма, пример на отвлечённом теле — плита, кронштейн, фасонный
корпус. Воспроизводимость даёт описание операции, а не имя изделия.
«Воспроизведено на кузове такого-то» → «воспроизведено на фасонном
корпусе».

**Приметы из папки проекта.** `check_docs.py --project "<папка>"` и хук
`commit-msg` добавляют к стоп-словам имя папки и имена лежащих в ней
моделей (`.SLDPRT`, `.SLDASM`, `.SLDDRW`, `.STEP` — `PROJECT_EXT` в
`tools/kit_local.py`). Папку можно запомнить для клона:
`git config solidworks.project "<папка проекта>"` (до 2.0.0 ключ был
`swkit.project` — переименовать).

## Что не попадает в репозиторий

`.gitignore` отсекает модели (`*.SLDPRT`, `*.SLDASM`, `*.SLDDRW`), экспорт
(`*.STEP`, `*.IGS`, `*.STL`…), вывод тестов `tests/vyvod/` со снимками,
метки блокировки `~$*`, `__pycache__` и стоп-лист `tools/stoplist.txt`.
Репозиторий — инструмент, а не архив проектов; проекты живут отдельными
папками. Снимки окна SolidWorks с моделью проекта не коммитятся (общее
правило снимков — skill-skill, 40-02).

## История: чем подтверждено

Проверка на посторонние проекты была в наборе с начала и пропускала
названия пять раз: только `knowledge/` (ушло через `CHANGELOG.md`), с
учётом регистра, без текста коммита, стоп-лист в публичном репозитории до
24.09.2026, глобальный рабочий автор у трёх коммитов 21.09.2026. Таблица
дыр, чего проверка не видит и сейчас, и правило «стоп-лист не в облаке» —
skill-skill, 40-02. Названия из старых коммитов вычищает только перепись
истории — решение владельца.

Шов слияния: две правки одного файла с разных машин сложились без
конфликта, и раздел правил начинался «раз в несколько сессий», а
заканчивался «перед коммитом обязателен». Отсюда — после `pull --rebase`
проверку заново и перечитать слитое.

До 2.0.0 (2026-10-28) у набора были свои хук `tools/hooks/commit-msg`,
`tools/check_msg.py` и полный `check_docs.py`; разбор PR шёл `gh pr merge
--rebase`. Теперь хук и проверки общие (skill-skill), PR сливается
`git merge --no-ff`.
