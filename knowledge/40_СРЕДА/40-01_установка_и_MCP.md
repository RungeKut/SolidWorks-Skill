# Установка и окружение

## Клон

Общий порядок (папка скиллов агента, хук, автор, стоп-лист, обновление) —
соседний скилл skill-skill, `knowledge/40_СРЕДА/40-01`. Для этого набора:

```bash
git clone https://github.com/RungeKut/SolidWorks-Skill.git "<папка скиллов>/solidworks"
cd "<папка скиллов>/solidworks"
git config core.hooksPath ../skill-skill/hooks
git config user.name  "<публичное имя>"
git config user.email "<публичный адрес>"
python tools/check_docs.py
```

Свой стоп-лист набора — `tools/stoplist.txt` (локальный, в `.gitignore`),
вдобавок к общему; заводится руками, приметы изделий — до первого коммита
(40-02).

## Зависимости — руками, один раз на машину

Всё ставится в профиль пользователя, права администратора не нужны.

```powershell
# 1. Python 3.13 64-bit (если нет)
winget install --id Python.Python.3.13 --scope user --silent `
    --accept-package-agreements --accept-source-agreements

# 2. Разрядность — ОБЯЗАТЕЛЬНО 64bit, иначе дальше идти бессмысленно
$py = "$env:LOCALAPPDATA\Programs\Python\Python313\python.exe"
& $py -c "import platform; print(platform.architecture()[0])"

# 3. Мост к COM
& $py -m pip install --user pywin32

# 4. Библиотека набора импортируется из корня
& $py -c "import sys; sys.path.insert(0, r'<корень набора>'); import swkit; print('swkit', swkit.__version__)"

# 5. Связь с SolidWorks (SolidWorks должен быть запущен)
& $py -c "import win32com.client as w; a=w.GetActiveObject('SldWorks.Application'); print('OK', a.Visible)"
```

Python бывает и не в профиле (`C:\Python313` на машине с 2021, 40-03):
искать установленный, а не зашивать путь. `python` в PATH может оказаться
заглушкой Microsoft Store (skill-skill, 30-02).

`swkit` в Python не устанавливается намеренно: набор правится по ходу
работы, и шаг переустановки только мешал бы.

## Подключение swkit из скриптов

Корень набора — папка `SKILL.md`; переменные окружения не читаются
(skill-skill, 30-01). Скрипт внутри набора берёт корень от своего файла:

```python
import os, sys
ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))  # tests/x.py -> корень
sys.path.insert(0, ROOT)
import swkit as sw
```

Скрипт проекта лежит вне набора: в `templates/new_project/build.py` корень
вписывается в `KIT` при копировании шаблона в проект; пока шаблон лежит в
наборе, корень находится от `__file__` (20-05, «Новый проект»).

## Запуск SolidWorks, если он не запущен

`swkit` подключается к **уже запущенному** SolidWorks: холодный старт
занимает больше минуты, а подключиться можно только после регистрации
приложения в таблице запущенных объектов (ROT). До неё `GetActiveObject`
бросает исключение, и `sw.app()` поднимет **второй** экземпляр.

```powershell
Start-Process "C:\Program Files\SOLIDWORKS Corp\SOLIDWORKS\SLDWORKS.exe"
```

Ожидание готовности — циклом, а не паузой наугад:

```python
import time
import pythoncom
import win32com.client
import win32com.client.dynamic

pythoncom.CoInitialize()
app, t0 = None, time.time()
while app is None and time.time() - t0 < 420:
    try:
        app = win32com.client.dynamic.Dispatch(
            win32com.client.GetActiveObject("SldWorks.Application"))
    except Exception:
        time.sleep(3)
if app is None:
    raise RuntimeError("SolidWorks не поднялся за 7 минут")
```

Дальше — обычное `sw.app()`: оно подключится к этому же экземпляру и
поставит сторож модальных окон.

**Окно после такого старта невидимо**: сразу после регистрации в ROT
`app.Visible` равно `False`. `sw.app()` ставит `Visible = True` сам; при
прямой работе с COM выставлять явно, иначе построение идёт вслепую и
снимки берутся с несуществующего окна.

Проверено 21.09.2026 на 2021 SP05.1: после такого запуска обе сквозные
проверки из `tests/` проходят целиком.

## Требования, нарушение которых ломает всё

* **Python только 64-bit.** 32-битный не получит COM-объект 64-битного
  SolidWorks.
* **SolidWorks в интерактивной сессии**, не служба и не заблокированный
  RDP: без рабочего стола ломаются виды и снимки.
* **Единицы API — метры и радианы.**

## Два MCP-сервера

Для работы `swkit` **не нужны**, ставятся отдельно.

| Сервер | Транспорт | Что даёт |
|---|---|---|
| `solidworks` | stdio, локальный | 132 инструмента управления SolidWorks |
| `swapi-pilot` | HTTP, внешний | поиск по официальной документации API |

```powershell
claude mcp add solidworks --scope user -- `
    "C:\dev\SolidworksMCP-python\.venv\Scripts\python.exe" `
    "C:\dev\SolidworksMCP-python\src\utils\start_local_server_claude.py" `
    --real --year 2025
claude mcp add swapi-pilot --scope user --transport http https://swapi-pilot.com/mcp
```

* **Ключ `--real` обязателен.** Без него сервер стартует в **mock-режиме**
  и отвечает «готово» на все команды, ничего не делая
  (`mock_mode = not args.real`).
* Ключ `--year` называет версию SolidWorks: на машине с 2021 —
  `--year 2021` (40-03).
* После изменения конфигурации MCP нужен перезапуск Claude Code.
* **Данные `swapi-pilot`.** Внешний сервис: туда уходят поисковые запросы
  по API — имена методов и интерфейсов; геометрия и файлы моделей не
  уходят. При строгой политике по данным у локального сервера есть свой
  поиск: `search_solidworks_api_help`, `lookup_api_method`,
  `lookup_api_interface`, `find_related_api_members`.

## Когда MCP, а когда swkit

| Задача | Чем |
|---|---|
| Разовое действие, разведка | MCP `solidworks` |
| Найти сигнатуру, перечисление, пример | `swapi-pilot`, `search_solidworks_api_help` |
| Построение проекта, повторяемость, проверки | **`swkit`** |

Причина разделения не в качестве сервера, а в характере задачи: реальному
моделированию нужны точные вызовы с двумя десятками позиционных аргументов
и проверка результата на каждом шаге, а обобщённые обёртки этого не дают.

## История

До 2.0.0 (2026-10-28) набор жил в `<клон>\skill`, а `tools/setup.ps1`
(и `Install-skill.bat` над ним) создавал junction из папок скиллов Claude
Code и Kimi Code в `<клон>\skill` (для opencode — отдельной командой
`mklink /J`), прописывал переменную окружения с корнем, включал хук,
заводил стоп-лист, проверял Python и ставил `pywin32`. Отказались по общему
решению skill-skill (30-01): переменная переживает перенос клона и ведёт в
пустоту. Наблюдения той поры, не потерявшие смысла:

* junction создаётся без прав администратора, симлинк — нет;
  PowerShell 5.1 не заходит в junction при `Get-ChildItem -Recurse` —
  проверять `Test-Path` на конкретный файл;
* копия набора в папке второго агента расходится с первой незаметно —
  правка в одной не появляется в другой (то же у двух клонов без push и
  pull, skill-skill 40-01);
* opencode требует `name` из 1–64 строчных латинских букв с одиночными
  дефисами, равный имени папки скилла, и `description` 1–1024 знака; при
  «: » без кавычек скилл молча не грузится (skill-skill, 30-06);
* в Windows PowerShell 5.1 при `$ErrorActionPreference = "Stop"` вывод
  нативной программы в stderr становится терминирующей ошибкой — на время
  такого вызова ставить `Continue`.
